## 3. Erreurs critiques (celles du plan, en phrases d'apprenant, dans l'ordre du plan)

- E1 « Mon fichier .php s'ouvre par double-clic : je le vois, donc ça marche. » Ouvrir le fichier par son chemin disque (`file://`) au lieu de passer par `localhost` : le navigateur lit le fichier lui-même, sans Apache ni PHP, et affiche le code au lieu de la page.
- E2 « Apache, c'est ma base de données. » Croire qu'Apache est une base de données : Apache sert les pages ; c'est le SGBD (MariaDB, appelé MySQL dans le panneau) qui range les données, et seul PHP l'interroge.
- E3 « Je copie mon XAMPP sur le serveur du client, ça marchera pareil. » Mettre XAMPP en production : ses réglages sont ceux d'un poste de développement (compte root sans mot de passe, phpMyAdmin ouvert à qui le trouve, erreurs affichées) ; un serveur public se configure autrement.
- E4 « Je tape localhost et je vois la page du paquet : mon fichier n'est pas servi. » Visiter localhost au lieu de localhost/projet : localhost est la page d'accueil du serveur, le chemin /projet est celui du dossier de l'apprenant dans la racine.

Chaque erreur a une étape d'explication qui la montre (E1 : « Le trajet d'une page » ; E2 : « Le trajet d'une page » ; E3 : « Pas en production » ; E4 : « Le trajet d'une page »), un essai de l'intuition (E2, E3, E4 ; E1 est parié dans la perception, « Ton pari », et repris en fin de bloc), un item de pratique qui la révèle (`data-erreur`), un retour qui nomme l'élément du modèle en cause et au moins une différée qui la touche.

## 4. Le modèle du bloc

Système enseigné : **une page PHP n'existe qu'au bout d'un trajet : le navigateur demande à Apache, qui la sert à partir du dossier racine du serveur ; Apache passe le fichier à PHP, qui exécute le code ; PHP interroge le SGBD si la page a besoin de données ; la réponse revient au navigateur. L'adresse choisit le trajet (`http://localhost/…` passe par Apache et PHP, `file://…` ne passe par aucun des deux), et chaque panne coupe ou détourne le trajet à un étage que le symptôme désigne.**

Éléments : navigateur, adresse (http ou file, hôte `localhost`, port, chemin), Apache (le serveur web), dossier racine (htdocs), dossier `projet`, fichier `index.php`, PHP (le langage et son interpréteur), SGBD (MariaDB, appelé MySQL), base, phpMyAdmin (une page web qui pilote le SGBD), port 80 (Apache) et port 3306 (SGBD), panneau de contrôle (ou `lampp`), terminal, PATH, `php -v`, le programme qui occupe un port, le paquet (XAMPP, MAMP, XAMPP pour Linux), le serveur de production.

Relations (types pour la conception ; à l'écran tout est dit en mots) :

- Composition : un paquet = Apache + PHP + un SGBD + phpMyAdmin ; une URL `http://localhost/projet/` = schéma, hôte, chemin.
- Catégorie : XAMPP, MAMP et XAMPP pour Linux sont trois paquets de la même sorte ; Apache, PHP, le SGBD sont trois programmes du trajet ; les trois pannes sont trois sortes de symptôme.
- Opposition : Apache contre SGBD ; `http://localhost` contre `file://` ; poste de développement contre production ; `localhost` contre `localhost/projet` ; page de PHP exécuté contre code affiché.
- Condition : PHP ne s'exécute que si la requête passe par Apache ; Apache ne sert que ce qui est dans sa racine ; phpMyAdmin n'affiche les bases que si le SGBD tourne ; `php -v` n'est trouvé que si le dossier de PHP est dans le PATH, ou si on l'appelle par son chemin complet ; Apache ne démarre que si son port est libre.
- Équivalence : le chemin de l'URL reprend l'arborescence sous la racine (`C:\xampp\htdocs\projet` = `/projet`) ; `http://localhost` = `http://localhost:80` ; `localhost` = la machine elle-même (127.0.0.1).
- Cause : un port occupé empêche Apache de démarrer, donc plus de réponse ; un fichier hors de la racine donne un 404 ; un double-clic fait lire le fichier par le navigateur seul.
- Séquence : installer, démarrer Apache et le SGBD, poser `index.php` dans `htdocs/projet`, taper `localhost/projet`, créer la base dans phpMyAdmin.
- **Relation centrale** : « le code PHP s'exécute sur le serveur, jamais dans le navigateur : seule l'adresse `http://localhost` fait passer la requête par Apache et PHP, et chaque panne coupe le trajet à un étage que le symptôme désigne ». À l'écran : « avant de dire que la page marche, demande qui l'a lue : Apache et PHP, ou le navigateur seul ? ».
- Ce que le système produit et qu'aucun élément seul ne contient : dire, d'après ce qu'on voit (du code, un 404, aucune réponse, un démarrage qui échoue), à quel étage le trajet est coupé, donc quoi corriger ; et savoir qu'un paquet qui marche sur un poste n'est pas un serveur public.
- Frontières : dedans, ce qui précède. Dehors : tout ce que liste la section 1 (hors objectif).
- À quoi ça sert dans le métier : tout le PHP et ses bases se développent sur un serveur local, qui reproduit la chaîne HTTP du bloc sur le Web ; la plupart des pannes d'un poste de développeur sont ces trois-là ; la distinction poste / production évite d'exposer un serveur réglé pour la commodité ; le bloc suivant ouvre un compte en ligne pour garder ce travail.

Schéma du bloc (règle C08), une chaîne : « l'adresse et ce que le programme du poste fait au départ » → (ce que l'adresse fait faire au navigateur) → « qui lit le fichier » → (ce que ce lecteur en fait) → « ce que voit l'apprenant ». Montré rempli dès la première étape pour Yasmine (page servie par localhost/projet, base dans phpMyAdmin) ; le pari (double-clic) est repris et corrigé en fin de bloc ; le schéma est construit par l'apprenant pour un cas nouveau : Noah (29 ans, sous Linux, XAMPP pour Linux) a déjà un autre serveur sur le port 80, clique sur démarrer Apache, puis, ne voyant rien servi, double-clique son `index.php` (le cas combine deux notions montrées séparément : un port occupé et le double-clic, et n'est aucun des cas du cours).

## 5. Fil rouge : « Le serveur de Yasmine »

Une seule histoire. Personnages : Yasmine, 34 ans (la même que B04 à B11), sur son PC Windows, avec XAMPP ; Farid, son ami de formation, sur son Mac, avec MAMP ; Noah, 29 ans, sous Linux, pour le cas nouveau de l'ensemble et quelques cartes (comme dans B10 et B11). Le formateur demande à Yasmine de servir une page PHP depuis son poste et d'y ranger une base. Gestes qui portent les notions :

1. Yasmine installe XAMPP, démarre Apache et MySQL, tape `localhost` et voit la page d'accueil du paquet (N1, N2, N3).
2. Elle crée le dossier `projet` dans `htdocs`, y écrit `index.php`, tape `localhost/projet` et voit sa page (N4, N5).
3. Elle double-clique sur `index.php` et voit le code (N7). Elle ouvre phpMyAdmin et crée une base (N8, N9). Elle lance `php -v` (N10).
4. Trois pannes lui arrivent : Apache arrêté, un fichier au mauvais endroit, un port pris par un autre programme (N11, N12, N13) ; Farid, lui, croit qu'Apache est sa base de données (N6) ; le formateur dit pourquoi on ne met pas XAMPP en ligne (N14).

Le fil porte les notions : si une notion n'a pas sa place dans l'histoire, l'histoire change, pas la notion.

## 8. Le tableau d'alignement et la liste

Une ligne par notion de la section 10, une ligne par relation centrale (`relations`), une ligne pour le tout (`ensemble`), avec `hors_objectif`. Chaque ligne : l'étape qui la montre, ce qui l'entraîne, les questions qui l'interrogent.

« La liste avant d'écrire un écran » d'AGENTS.md, recopiée mot pour mot (à avoir sous les yeux à chaque écran) :

Trois blocs ont fait la même dizaine de fautes, trouvées après coup par les épreuves ou par Amine. La machine en attrape une partie ; le reste se relit à l'écriture de chaque écran, cette liste sous les yeux, puis à la relecture de la fiche. Une faute de cette liste trouvée aux épreuves est une faute de méthode, pas de hasard.

1. **L'écran se résout avec ce qu'il montre.** La règle, la convention, la donnée qu'il faut sont écrites plus haut sur l'écran ou dans l'encadré « Pour lire » ; rien n'est expliqué trois écrans plus loin (B03 : le disque de 931 Go). Une règle montrée sur un seul exemple n'est pas enseignée.
2. **Une consigne, une question.** Le rappel va dans l'encadré ; la question tient en une phrase, un seul temps (« relève, puis juge » fait deux items), et ne souffle pas sa réponse.
3. **Le retour oriente, il ne répond pas.** Une question ou un indice sur la notion ; ni les mots de la bonne option, ni l'attendu, ni la solution. L'encadré « Pour lire » redit une convention, pas la règle que l'exercice vérifie (B03 : « Le vendeur »).
4. **Le mot est celui du modèle**, défini avant d'être employé (« architecture », pas « famille ») ; un mot du métier qui n'est pas défini (tableur, rendu, export, tour) se remplace ou se définit sur place.
5. **Rien de la conception.** Pas de temps ni d'étape numérotés, d'identifiant d'onglet, de nom de classe, d'étiquette de la méthode, de gabarit « [seulement si l'essai est faux] » dans le texte.
6. **La situation revient et l'écran se lit sur un téléphone.** Chaque écran repart de l'histoire du bloc, quatre écrans abstraits d'affilée au plus ; un calcul s'écrit en lignes, pas en ligne continue ; pas une douzaine de noms ou de codes d'un coup (B03, ET8).
7. **Peu de prénoms**, un par cas, le même d'un bout à l'autre du cas (B03 en avait 17).
8. **La charge se compte en écrivant.** Les saisies de l'écran s'ajoutent au total du bloc (B03 : environ 115) ; un exercice qui n'apporte ni notion ni erreur nouvelle se fond dans un autre.
9. **Ce qui se fait hors de la page a son constat** (règle F06), et le mot de l'outil est vérifié (« Enregistreur audio » sous Windows 11 ?).
10. **La grille se recompte avec la fiche** : chaque nombre, chaque citation, la version.

## 9. Contraintes de style et de fond

- Français, tutoiement, accents, aucun tiret cadratin (ni — ni –), phrases courtes, un mot du métier défini avant d'être employé. Un mot, un seul sens du début à la fin : « serveur » (un programme qui répond à des requêtes, défini en ET4 « localhost »), « Apache » (le serveur web du paquet), « SGBD » (le programme qui range les données, défini avant son emploi, avec « MariaDB » et « MySQL » dits dans la même phrase), « racine » (le dossier que le serveur publie, défini en ET4), « port » (acquis du bloc sur le Web, redonné), « paquet » (XAMPP, MAMP : le programme qui installe d'un coup Apache, PHP, le SGBD et phpMyAdmin, défini en ET5), « phpMyAdmin » (une page web, définie en ET6), « panneau de contrôle » (la fenêtre où l'on démarre et arrête les programmes du paquet), « interclassement » (la règle qui compare et trie les textes d'une base, dit « collation » en anglais), « production » (le serveur public où le site est en ligne).
- Le texte de l'apprenant ne dit rien de la conception : pas « étape N », pas « Avant de lire », pas de nom de classe, d'identifiant d'onglet, de temps numéroté.
- Chaque écran se résout avec ce qu'il montre : la donnée (la ligne lue, la réponse du terminal, l'adresse) est imprimée sur l'écran ; ce que fait chaque commande, chemin ou bouton cité est redonné dans un encadré « Pour lire » (une convention, jamais la conclusion de l'exercice).
- Un exercice du cours se pose AVANT le texte qui répond ; ce texte ne paraît qu'une fois l'exercice fini. Une consigne, une question ; le retour d'une option fausse et les coups de pouce sont des questions qui orientent.
- Un écran, une notion, au plus trois mots nouveaux ; quatre écrans abstraits d'affilée au plus ; le serveur de Yasmine revient dans chaque étape.
- **Un paquet par système, dit** : XAMPP sous Windows (racine `C:\xampp\htdocs`, terminal PowerShell, parce que XAMPP est un programme de Windows et non de la fenêtre d'Ubuntu), MAMP sous macOS (racine `/Applications/MAMP/htdocs`, Terminal), XAMPP pour Linux sous Linux (racine `/opt/lampp/htdocs`, terminal). La page ne dit jamais « XAMPP, MAMP ou LAMP au choix ».
- **Le port d'Apache** : 80 pour XAMPP ; MAMP l'écrit dans ses préférences et, d'après la mémoire de l'auteur, propose 8888 par défaut. La fiche enseigne la règle (le port se lit dans le paquet ; 80 ne s'écrit pas, un autre port s'écrit après `localhost:`) et dit « le port d'Apache » partout où le cas n'est pas celui de Yasmine.
- **Faits joués** sur Ubuntu : `php -v` écrit « PHP » suivi de la version sur sa première ligne ; le serveur intégré de PHP répond 200 pour une page qui existe et 404 pour un chemin faux ; un fichier PHP lu avec `cat` montre son code et, servi, montre son résultat ; `lsof -i :PORT` écrit des colonnes COMMAND, PID, USER, FD, TYPE, DEVICE, SIZE/OFF, NODE, NAME, et la ligne d'un programme qui écoute finit par `(LISTEN)` ; `curl` répond « Failed to connect … Couldn't connect to server » quand rien n'écoute.
- **Faits non joués, à vérifier sur machine** (la page n'en cite le texte exact que lorsque la mémoire de l'auteur est sûre ; sinon elle dit « un message le dit ») : (a) Windows : l'installateur de XAMPP, le dossier `C:\xampp`, le panneau de contrôle et ses boutons Start, `C:\xampp\php\php.exe`, `Get-NetTCPConnection -LocalPort 80` et `Get-Process -Id`, le message du panneau quand le port est pris, le message du navigateur quand Apache est arrêté ; (b) macOS : MAMP, ses préférences et son port, `/Applications/MAMP/htdocs`, le dossier de PHP sous `/Applications/MAMP/bin/php`, `lsof -i` sans `sudo` ; (c) Linux : l'installateur de XAMPP pour Linux, `sudo /opt/lampp/lampp start`, `/opt/lampp/htdocs` et ses droits, `sudo /opt/lampp/bin/php`, `sudo lsof -i :80` ; (d) phpMyAdmin : l'adresse `localhost/phpmyadmin`, le formulaire de création d'une base et le nom « Interclassement », le message quand le SGBD est arrêté ; (e) la page d'accueil du paquet sur `localhost` ; (f) le serveur intégré de PHP sur le port 80 sous Windows et macOS. Chacun est noté « non joué » dans le compte rendu.
- Accessibilité : chaque listing est un `<pre class="listing">` avec son `data-lecture` ; aucune capture d'écran : le navigateur et le panneau se montrent par un dessin à description (`role="img"` et `aria-label`), jamais par une image muette ; rien ne déborde à 390 px.
- Poids : moins de 5 Mo.

## 10. Les notions à couvrir

14 notions, chacune dans au moins une relation (section 4).

- N1 Un paquet (XAMPP, MAMP, XAMPP pour Linux) installe d'un coup Apache, PHP, le SGBD et phpMyAdmin ; un paquet par système ; s’installe hors des dossiers protégés, composants cochés, sans lancer le panneau en administrateur au quotidien. LAMP désigne une pile, pas un produit.
- N2 Démarrer et arrêter Apache et le SGBD : panneau de contrôle (Windows, macOS), `lampp start` et `lampp stop` sous Linux, qui n'ouvre aucun panneau ; l'état se lit dans le panneau.
- N3 `localhost` est la machine elle-même (127.0.0.1) ; `http://localhost` vaut `http://localhost:80`, un autre port s'écrit après deux-points ; `localhost` seul montre la page d'accueil du paquet.
- N4 Le serveur ne publie que le contenu de son dossier racine ; le chemin de l'URL reprend l'arborescence sous la racine ; le dossier `projet` créé dedans donne `/projet`.
- N5 Un `index.php` minimal : une balise d'ouverture PHP, une instruction d'affichage (`echo`), une balise de fermeture ; ce que le navigateur reçoit est le résultat ; `index.php` est ce que le serveur sert quand l'adresse nomme un dossier.
- N6 Les rôles : le navigateur demande, Apache sert, PHP exécute, le SGBD range ; seul PHP interroge le SGBD ; Apache n'est pas une base de données.
- N7 `file://` contre `http://` : un chemin disque s'ouvre en `file://`, le navigateur lit lui-même le fichier, sans Apache ni PHP, donc il affiche le code ; le double-clic fait cela.
- N8 Le SGBD s'appelle MySQL dans l'interface mais c'est MariaDB ; il écoute sur le port 3306, Apache sur le 80 ; une base contient des tables.
- N9 phpMyAdmin est une page web du paquet (`localhost/phpmyadmin`) qui pilote le SGBD ; il demande un SGBD qui tourne ; créer une base : un nom et un interclassement.
- N10 `php -v` écrit la version de PHP dans le terminal ; le dossier de PHP du paquet n'est pas dans le PATH : on appelle `php` par son chemin complet.
- N11 Panne « Apache arrêté » : aucune réponse du serveur ; le navigateur ne peut pas se connecter ; on lit l'état dans le panneau et on démarre Apache.
- N12 Panne « port 80 occupé » : Apache refuse de démarrer, un message le dit ; un programme écoute déjà sur ce port ; on lit lequel (`lsof -i :80`, `Get-NetTCPConnection`) ; on l'arrête, ou on met Apache sur un autre port (l'URL devient `localhost:8080/projet`).
- N13 Panne « mauvais dossier » : Apache répond, mais 404 : le fichier n'est pas sous la racine ou le nom du dossier n'est pas celui de l'URL ; on compare le chemin réel du fichier et l'adresse.
- N14 XAMPP et MAMP sont réglés pour le poste de développement (root sans mot de passe, phpMyAdmin ouvert, erreurs affichées) ; un serveur public se configure autrement ; on ne les met pas en production.
