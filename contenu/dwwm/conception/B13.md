## 1. Identité du bloc

- Bloc `B13`, formation `dwwm`, type `procedures`. Le plan range P3.6 en « Procédure, conventions ». `composition.ts` accepte un type seul ou une liste (`TypeDuBloc`) parmi `systemes`, `procedures`, `regles_cas`, `conventions`. Trois choix étaient possibles.
  - `conventions` ne tire que des explications en différée, sans tâche ni transfert : or la preuve du plan est faite de gestes (ouvrir un compte, l'activer, demander un pack) et de lectures qui se vérifient (une durée, un montant, une condition). Les « conventions » du plan (écart B2) ne sont d'ailleurs nommées dans aucune notion : le nom d'utilisateur sobre est donné comme un conseil, jamais comme une règle de GitHub.
  - `systemes` tire des transferts « choisir la méthode » et « hors champ » : le hors champ est non déductible par construction (classe de défaut de B09), et il n'y a pas de méthode à choisir quand le geste est le même pour tous.
  - `procedures` tire des tâches à réponse exacte et des transferts « adapter la condition » et « trouver l'erreur ». C'est ce que demande la preuve : ouvrir un compte et le protéger, demander le pack, lire trois offres (des nombres, des mois qu'un seul texte exprime : 312, mars 2027, janvier 2028), et trouver l'erreur dans un cas donné (croire qu'un crédit continue, croire que GitHub Pages exécute du PHP). La partie « système » de la preuve (dire en deux phrases Git contre GitHub, dire si un hébergement exécute PHP) est tenue par les six questions de restitution, par des explications en différée et par le schéma construit en fin de bloc : le type `procedures` ne retire pas le modèle.
    Choix : `procedures`, avec des explications en différée comme B11 et B12. Dosage de T01 pour « procédures et outils » : démonstration, pratique abondante, explication courte avant de faire.
- Titre : « GitHub et le Student Developer Pack ». Titre court : « GitHub et le pack ».
- Partie : P3 « Le poste du développeur », sixième et dernier bloc. Dans le texte, le bloc précédent n'est pas renvoyé par un numéro ; le suivant n'est dit que par ce qu'il apporte (la double authentification reprise pour tous les comptes).
- Prérequis du manifeste : `["B11", "B12"]`. Le plan donne P3.4 (B11, « Choisir et prendre en main son éditeur », où JetBrains est vu comme IDE) ; l'écart C1 du contrôle ajoute P3.5 (B12, « Un serveur web local »), car savoir qu'un fichier PHP s'exécute côté serveur vient de B12. La carte de la partie P3 dit encore que P3.4 et P3.6 sont indépendants : c'est un défaut du plan, noté ici et en section 13, non corrigé dans cette PR.
- Objectif du manifeste, mot pour mot : l'objectif élargi de la section 2. Il se lit en puces, un attendu par « ; ».
- **Un atelier obligatoire** (règle F06), sur le compte et le téléphone de l'apprenant : créer le compte, installer l'application d'authentification, activer la double authentification, ranger les codes de récupération, lire l'état de la protection, demander le pack, lire trois offres, classer trois hébergements, regarder où en est sa demande. Neuf écrans, douze critères de constat. **Jamais de mot de passe ni de code demandé à la page** : le constat est une série de critères que l'apprenant coche d'après ce qu'il lit chez GitHub et ce qu'il écrit sur son papier. Pas d'aisance : le plan ne donne ni automatisme ni cible chronométrée à ce bloc, donc pas d'étape `aisance`.
- **Le statut doit être réel** : la fiche dit que la preuve est celle de l'apprenant, ne montre aucun moyen de contourner la vérification, et ne dit rien de ce que les conditions du service interdisent au-delà de ce que la documentation lue énonce (la notion 19 du contrôle, « revendre ou acheter un compte est interdit », n'a pas été retrouvée dans la documentation lue : elle n'est pas écrite, voir la section 14).

La fiche le traite à part : il n'est pas l'une des trois offres lues, mais il est le piège (croire qu'il exécute PHP) et le cas de l'hébergement statique.

### Objectif élargi proposé

## 3. Erreurs critiques (celles du plan, en phrases d'apprenant)

- E1 « Git est installé sur mon PC, donc mon travail est sur GitHub. » Confondre Git et GitHub : Git est un logiciel du PC qui garde les versions ; GitHub est un service en ligne qui héberge des dépôts Git.
- E2 « Mon hébergement est gratuit pour toujours. » Croire qu'une offre est illimitée dans le temps : chaque offre s'arrête par une durée écoulée (24 mois, 12 mois), un statut qui finit ou un renouvellement qui n'a pas lieu ; « gratuit » ne dit pas « sans fin ».
- E3 « Je mets mon site PHP sur GitHub Pages, ça marchera comme chez moi. » Croire que GitHub Pages, ou un hébergement statique, exécute du PHP : il renvoie les fichiers tels quels.
- E4 « Je range ma liste de codes dans une note de mon téléphone. » (Ajoutée à celles du plan : le plan liste la double authentification parmi les ajouts, sans erreur critique dédiée ; la perte du téléphone est l'erreur la plus coûteuse du geste, et le plan dit « pas de 2FA » comme défaut du cours source.) La liste de codes de récupération rangée dans le téléphone qui porte l'application se perd avec lui ; GitHub ne rend pas l'accès à un compte protégé qui a perdu ses moyens de récupération.

Chaque erreur a une étape d'explication qui la montre (E1 : « Git et GitHub » ; E2 : « Trois offres, lues » ; E3 : « Héberger un site » ; E4 : « Un compte protégé »), un essai de l'intuition (E1 : p1, E2 : p2, E4 : p3 ; E3 est parié dans la perception, « Ton pari », et repris en fin de bloc), un item de pratique qui la révèle (`data-erreur` : E1 PR1-3, E2 PR1-5, E3 PR1-6 et PR1-7, E4 PR1-4), un retour qui nomme l'élément du modèle en cause et au moins une différée qui la touche.

## 4. Le modèle du bloc

Système enseigné : **un compte en ligne est protégé par un second élément en plus de son mot de passe ; il garde en ligne un travail que Git suit sur le PC ; le pack d'étudiant est un ensemble d'offres dont chacune dit un montant, une durée et une condition, et dont aucune n'est sans fin ; et un hébergement se juge sur ce qu'il exécute : du PHP côté serveur, ou seulement des fichiers statiques renvoyés tels quels.**

Éléments : Git, dépôt, version, GitHub, compte, adresse e-mail, nom d'utilisateur, mot de passe, double authentification (2FA), application d'authentification, secret, code TOTP, code de récupération, réglages du compte, pack (Student Developer Pack), partenaire, offre (montant, durée, condition), statut d'étudiant et preuve, GitHub Pro, assistant de code, hébergeur, crédit, site statique, côté serveur, GitHub Pages, Heroku, Microsoft Azure, JetBrains.

Relations (types pour la conception ; à l'écran tout est dit en mots) :

- Composition : un compte = une adresse e-mail, un mot de passe, un nom d'utilisateur ; une offre = un montant, une durée, une condition ; le pack = des offres de partenaires.
- Catégorie : Heroku, Microsoft Azure et JetBrains sont trois offres du même pack ; Heroku, Azure Static Web Apps et GitHub Pages sont trois hébergements, deux statiques et un qui exécute PHP.
- Opposition : Git contre GitHub ; une offre du pack contre un service de GitHub (GitHub Pages) ; un hébergement qui exécute PHP contre un hébergement statique ; un code affiché dans l'application contre une protection acceptée par GitHub.
- Condition : la double authentification demande un second élément (le code de l'application) ; les codes de récupération ne servent que s'ils sont rangés ailleurs que dans le téléphone ; le pack demande un statut vérifié ; une offre de partenaire peut avoir des conditions plus étroites que celles du pack ; la lecture d'une offre se date.
- Équivalence : l'adresse d'un profil = github.com + nom d'utilisateur ; 13 dollars par mois pendant 24 mois = 312 dollars.
- Cause : un statut qui prend fin arrête GitHub Pro ; une durée écoulée arrête un crédit ; un hébergement statique ne fait que renvoyer des fichiers, donc n'exécute pas PHP.
- Séquence : créer le compte, installer l'application, activer la double authentification, ranger les codes, demander le pack, lire les offres.
- **Relation centrale** : « chaque chose a sa place et sa limite : Git sur le PC, GitHub en ligne ; chaque offre a un montant, une durée et une condition, jamais sans fin ; un hébergement exécute du PHP ou renvoie des fichiers, rien entre les deux ». À l'écran : « avant de compter sur une offre, lis ce qu'elle donne, combien de temps et à quelle condition, et note la date ; avant de choisir un hébergement, demande ce qu'il exécute ».
- Ce que le système produit et qu'aucun élément seul ne contient : savoir, d'après la page officielle d'une offre, ce qu'on peut en attendre et jusqu'à quand, savoir où mettre un site selon ce qu'il contient, et garder l'accès à son compte quand le téléphone manque.
- Frontières : dedans, ce qui précède. Dehors : tout ce que liste la section 1 (hors objectif).
- À quoi ça sert dans le métier : un compte GitHub est la place où un développeur garde son travail et que l'on regarde ; il se protège avant qu'il soit volé. Le pack donne des outils et des crédits, mais un crédit qui s'éteint sans qu'on l'ait lu laisse une facture ou un site hors ligne. La partie suivante reprend la double authentification pour tous les comptes.

Schéma du bloc (règle C08), une chaîne : « le site et ce qu'il contient » → (ce que son contenu demande à l'hébergement) → « l'hébergement retenu » → (ce que son offre dit de sa durée) → « ce qui arrive ensuite ». Montré rempli dès la première étape pour Yasmine (le chemin d'un compte à une offre, ET2) ; le pari (GitHub Pages et une ligne PHP) est repris et corrigé en fin de bloc ; le schéma est construit par l'apprenant pour un cas nouveau : Noah (29 ans, sous Linux, étudiant vérifié) a un site à formulaire PHP à garder en ligne trois ans et lit l'offre de Heroku, dont le crédit dure 24 mois (le cas combine deux notions montrées séparément : l'hébergement qui exécute PHP et la durée d'une offre, et n'est aucun cas du cours ; il ne rejoue ni celui de Farid ni celui de la variante).

## 5. Fil rouge : « Le compte de Yasmine »

Une seule histoire. Personnages : Yasmine, 34 ans (la même que B04 à B12), sur son PC Windows ; Farid, son ami de formation, sur son Mac ; Noah, 29 ans, sous Linux, pour le cas nouveau de l'ensemble et quelques cas ; Lina et Samir n'apparaissent que dans des cas de différée, de restitution ou de variante. Le formateur demande à Yasmine d'ouvrir un compte GitHub et de le protéger, puis lui dit que les étudiants ont droit à des offres. Gestes qui portent les notions :

1. Yasmine ouvre son compte (N4), active la double authentification avec une application (N5, N6), range sa liste de codes de récupération (N7) et lit l'état de sa protection dans les réglages (N8).
2. Elle demande le pack avec la preuve qu'elle est étudiante (N9, N10, N19), voit GitHub Pro et un assistant de code qu'elle n'utilise pas (N11, N12).
3. Elle lit trois offres, Heroku, Microsoft Azure et JetBrains (N13, N14), et comprend qu'aucune n'est sans fin (N15).
4. Elle veut montrer son site d'exercice : elle apprend ce qu'est un site statique et ce que GitHub Pages n'exécute pas (N16, N17), et classe trois hébergements (N18).
5. Git sur son PC et GitHub en ligne sont distingués dès le début (N1 à N3).

Le fil porte les notions : si une notion n'a pas sa place dans l'histoire, l'histoire change, pas la notion.

## 8. Le tableau d'alignement et la liste

Une ligne par notion de la section 10, une ligne par relation centrale (`relations`), une ligne pour le tout (`ensemble`), avec `hors_objectif`. Chaque ligne : l'étape qui la montre, ce qui l'entraîne, les questions qui l'interrogent.

« La liste avant d'écrire un écran » d'AGENTS.md, recopiée mot pour mot (à avoir sous les yeux à chaque écran) :

Trois blocs ont fait la même dizaine de fautes, trouvées après coup par les épreuves ou par Amine. La machine en attrape une partie ; le reste se relit à l'écriture de chaque écran, cette liste sous les yeux, puis à la relecture de la fiche. Une faute de cette liste trouvée aux épreuves est une faute de méthode, pas de hasard.

1. **L'écran se résout avec ce qu'il montre.** La règle, la convention, la donnée qu'il faut sont écrites plus haut sur l'écran ou dans l'encadré « Pour lire » ; rien n'est expliqué trois écrans plus loin (B03 : le disque de 931 Go). Une règle montrée sur un seul exemple n'est pas enseignée.
2. **Une consigne, une question.** Le rappel va dans l'encadré ; la question tient en une phrase, un seul temps (« relève, puis juge » fait deux items), et ne souffle pas sa réponse.
3. **Le retour oriente, il ne répond pas.** Une question ou un indice sur la notion ; ni les mots de la bonne option, ni l'attendu, ni la solution. L'encadré « Pour lire » redit une convention, pas la règle que l'exercice vérifie (B03 : « Le vendeur »).
4. **Le mot est celui du modèle**, défini avant d'être employé (« architecture », pas « famille ») ; un mot du métier qui n'est pas défini (tableur, rendu, export, tour) se remplace ou se définit sur place.
5. **Rien de la conception.** Pas de temps ni d'étape numérotés, d'identifiant d'onglet, de nom de classe, d'étiquette de la méthode, de gabarit « [seulement si l'essai est faux] » dans le texte.
6. **La situation revient et l'écran se lit sur un téléphone.** Chaque écran repart de l'histoire du bloc, quatre écrans abstraits d'affilée au plus ; un calcul s'écrit en lignes, pas en ligne continue ; pas une douzaine de noms ou de codes d'un coup (B03, ET8).
7. **Peu de prénoms**, un par cas, le même d'un bout à l'autre du cas (B03 en avait 17).
8. **La charge se compte en écrivant.** Les saisies de l'écran s'ajoutent au total du bloc (B03 : environ 115) ; un exercice qui n'apporte ni notion ni erreur nouvelle se fond dans un autre.
9. **Ce qui se fait hors de la page a son constat** (règle F06), et le mot de l'outil est vérifié (« Enregistreur audio » sous Windows 11 ?).
10. **La grille se recompte avec la fiche** : chaque nombre, chaque citation, la version.

## 9. Contraintes de style et de fond

- Français, tutoiement, accents, aucun tiret cadratin (ni — ni –), phrases courtes, un mot du métier défini avant d'être employé. Un mot, un seul sens du début à la fin : « Git » (le logiciel du PC qui garde les versions), « GitHub » (le service en ligne), « dépôt » (un dossier dont un logiciel suit les changements), « service en ligne » (un programme qu'une entreprise fait tourner sur ses machines et que tu utilises par Internet, avec un compte), « double authentification » (en plus du mot de passe, un second élément), « secret » (une suite de caractères que seuls deux programmes connaissent), « code de récupération » (un code qui s'utilise à la place du code de l'application), « pack » (un ensemble d'offres), « partenaire » (une entreprise qui donne un avantage aux étudiants par le pack), « offre » (un avantage donné par un partenaire, avec son montant, sa durée et sa condition), « vérifié » (GitHub a contrôlé la preuve de statut), « hébergeur » (un service qui garde un site en ligne sur ses machines), « crédit » (une somme que l'hébergeur déduit de ta facture), « site statique » (des fichiers que le serveur renvoie tels quels), « côté serveur » (sur la machine du serveur, avant la réponse).
- Le texte de l'apprenant ne dit rien de la conception : pas « étape N », pas « Avant de lire », pas de nom de classe, d'identifiant d'onglet, de temps numéroté.
- Chaque écran se résout avec ce qu'il montre : la donnée (la ligne de l'offre, la condition du pack, le nom du fichier) est imprimée sur l'écran ou dans « Pour lire » ; ce que fait chaque mot anglais d'une page (credit, month, aged 16+, Enable) est redonné avec sa traduction ; l'encadré redonne une convention, jamais la conclusion de l'exercice.
- Un exercice du cours se pose AVANT le texte qui répond ; ce texte ne paraît qu'une fois l'exercice fini. Une consigne, une question ; le retour d'une option fausse et les coups de pouce sont des questions qui orientent.
- Un écran, une notion, au plus trois mots nouveaux ; quatre écrans abstraits d'affilée au plus ; le compte de Yasmine revient dans chaque étape.
- **Les offres sont datées** : chaque valeur d'une offre porte « lu le 16 novembre 2026 » (tableaux d'ET7, listing d'ET1). La fiche enseigne la lecture (page du pack, page du partenaire, date notée) et dit que la page du pack n'affiche pas de date. Aucune offre n'est donnée sans ces mots.
- **Aucun mot de passe, aucun code** : aucune consigne ni aucun critère ne demande de taper ou de donner un mot de passe, un code de la double authentification ou un code de récupération ; le papier de notes reçoit « où est rangée la liste », jamais un code.
- **Le statut doit être réel, l'IA n'est pas utilisée** : la preuve est celle de l'apprenant ; l'assistant de code est nommé et jamais activé.
- **Ce que la page ne dit pas ne se suppose pas** : Azure App Service (la page de l'offre ne dit pas s'il exécute PHP) est dit « à vérifier » ; ce que GitHub Pages affiche pour un fichier .php n'est pas affirmé.
- Accessibilité : chaque listing est un `<pre class="listing">` avec son `data-lecture` ; aucune capture d'écran : la page d'inscription et le téléphone se montrent par un dessin à description (`role="img"` et `aria-label`), jamais par une image muette ; rien ne déborde à 390 px.
- Poids : moins de 5 Mo.

## 10. Les notions à couvrir

19 notions, chacune dans au moins une relation ou une question (section 4 et alignement).

- N1 Git est un logiciel du PC qui suit les changements des fichiers d'un dépôt et garde chaque version, sans Internet ni compte.
- N2 GitHub est un service en ligne qui héberge des dépôts Git, demande un compte et propose d'autres services ; avoir Git ne met rien sur GitHub.
- N3 Dire en deux phrases ce qui distingue Git et GitHub.
- N4 Un compte GitHub se crée avec une adresse e-mail, un mot de passe et un nom d'utilisateur ; l'adresse du profil est github.com puis le nom.
- N5 Un mot de passe seul protège mal ; la double authentification ajoute un second élément que seul le téléphone calcule.
- N6 Le code de l'application est calculé à partir d'un secret reçu au scan du carré et de l'heure, sans réseau.
- N7 Les codes de récupération remplacent le code de l'application et se rangent hors du téléphone.
- N8 La double authentification se constate dans les réglages du compte ; un code affiché dans l'application ne le prouve pas.
- N9 Le pack est un ensemble d'offres de partenaires, ouvert aux étudiants que GitHub a vérifiés.
- N10 Conditions pour demander le pack : au moins 13 ans, une formation qui délivre un diplôme, une preuve de statut ; les enseignants ne sont pas éligibles ; le statut doit être réel.
- N11 Le pack donne GitHub Pro, non Enterprise, tant que l'on est étudiant.
- N12 Le pack contient un assistant de code, qu'on n'utilise pas pendant l'apprentissage.
- N13 Une offre se lit en trois choses, le montant, la durée et la condition, sur la page du pack et sur celle du partenaire ; on note la date de sa lecture.
- N14 Les trois offres lues : Heroku (13 dollars par mois pendant 24 mois), Azure (100 dollars, 12 mois), JetBrains (un an, renouvelé chaque année).
- N15 Aucune offre n'est sans fin : durée écoulée, crédit dépensé ou statut terminé ; les valeurs changent et se datent.
- N16 Un site statique est renvoyé tel quel ; PHP s'exécute côté serveur ; JavaScript s'exécute dans le navigateur.
- N17 GitHub Pages est un service de GitHub, distinct du pack, qui publie des fichiers statiques et n'exécute pas de PHP.
- N18 Classer une offre d'hébergement : Heroku exécute du PHP ; Azure Static Web Apps et GitHub Pages servent du statique ; ce que la page ne dit pas ne se suppose pas.
- N19 Le pack s'active après une demande ; l'état se lit sur la page du pack, qui ne donne pas de délai.
