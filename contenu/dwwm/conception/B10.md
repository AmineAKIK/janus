## 3. Erreurs critiques (celles du plan, inchangées, en phrases d'apprenant)

- E1 « Je supprime avec `rm`, et je le retrouverai dans la corbeille. » Croire que `rm` passe par la corbeille : `rm` retire le nom pour de bon, sans corbeille et sans demander.
- E2 « Je colle cette ligne `rm -rf` ou `sudo rm` trouvée sur un forum, elle doit être sans danger. » Lancer `rm -rf` ou `sudo` par copier-coller : `-r` descend dans les sous-dossiers, `-f` ne demande rien, `sudo` retire la protection des fichiers du système ; on lit la commande, les options, les chemins et le dossier où l'on est avant d'appuyer sur Entrée.
- E3 « `cp -R site sauvegarde` fait la même chose, que `sauvegarde` existe ou non. » Croire que `cp -R foo bar` donne le même résultat que `bar` existe ou non : absent, `bar` devient la copie ; existant, la copie se range dedans, sous `bar/foo`.
- E4 « Cette ligne de Cmd marchera dans ma fenêtre d'Ubuntu, ou l'inverse. » Appliquer la syntaxe Cmd dans bash ou l'inverse : le séparateur de chemin, l'écriture des options et le nom des commandes ne sont pas les mêmes.

Chaque erreur a un essai de l'intuition, une étape d'explication qui la montre (E1 : « Supprimer » ; E2 : « Supprimer » ; E3 : « Copier » ; E4 : « Et sous Cmd ? »), un item de pratique qui la révèle (`data-erreur`), un retour qui nomme l'élément du modèle en cause, et au moins une différée qui la touche. Les identifiants sont ceux du plan, dans l'ordre du plan.

## 4. Le modèle du bloc

Système enseigné : **une commande de manipulation lit ses morceaux (options, source, destination) et agit sur l'arbre des dossiers à l'endroit que ses chemins désignent, sans te déplacer. Ce que fait `cp` ou `mv` dépend du nom de la destination : un nom qui n'existe pas devient le nouveau nom ; un dossier qui existe reçoit l'élément dedans ; un fichier qui existe est remplacé sans question. `rm` n'a pas de destination : il retire pour toujours. Une commande qui échoue ne change rien. On peut donc dire l'état de l'arborescence avant d'appuyer sur Entrée.**

Éléments : arborescence (les dossiers et les fichiers rangés les uns dans les autres), dossier d'atelier, répertoire courant, chemin (absolu, relatif, `.`, `..`), source, destination, commande (`mkdir`, `touch`, `ls`, `cp`, `mv`, `rm`), option (`-p`, `-R`, `-r`, `-v`, `-f`, `-i`), message d'erreur, silence d'une commande réussie, état (ce qui existe, sous quel nom, dans quel dossier), `sudo` ; côté Windows : Cmd, `copy`, `move`, `del`, `rmdir /s`, l'antislash.

Relations (types pour la conception ; à l'écran tout est dit en mots) :

- Composition : une arborescence = des dossiers et des fichiers rangés les uns dans les autres ; une ligne `cp -R site sauvegarde` = commande + option + source + destination ; une sauvegarde = une copie de toute l'arborescence.
- Catégorie : `-R` et `-r` sont deux écritures de la même option (`cp`, `rm`) ; `mkdir -p`, `rm -r`, `cp -R` sont des options qui agissent sur plusieurs niveaux ; `copy`, `move`, `del`, `rmdir /s` sont les noms de Cmd pour les mêmes gestes.
- Opposition : destination absente contre destination existante (E3) ; `rm` contre une corbeille (E1) ; `-f` (ne rien demander) contre l'absence d'option (échec sur un nom absent) ; avec `sudo` contre sans `sudo` (E2) ; `/` contre `\` ; `-r` contre `/s` ; `cp` contre `copy` (E4) ; `mkdir` contre `mkdir -p` (parent absent).
- Condition : `mkdir`, `touch` et `cp` n'agissent que si le dossier parent du chemin existe ; `cp` copie un dossier seulement avec `-R` ; `rm` retire un dossier seulement avec `-r` ; `mv` refuse un dossier dans lui-même ; une commande Cmd ne marche que dans Cmd.
- Équivalence : `cp -R` et `cp -r` ; `mv` d'un dossier emporte son contenu sans option, comme `-R` pour `cp` ; `copy` pour `cp`, `move` pour `mv`, `del` pour `rm` d'un fichier, `rmdir /s` pour `rm -r` ; `.` comme destination désigne le répertoire courant.
- Cause : l'existence de la destination décide du résultat de `cp -R` et de `mv` (nouveau nom ou rangé dedans) ; `-v` fait écrire chaque copie, d'où la sauvegarde que l'on lit ligne à ligne ; `rm -f` fait taire le nom absent, d'où l'absence de message ; `-r` fait descendre `rm` dans le dossier, d'où la destruction du contenu ; `sudo` fait agir `rm` en administrateur, d'où la destruction de ce que le compte n'avait pas le droit de toucher.
- Séquence : lire une ligne `rm -r` avant de la lancer, dans l'ordre : la commande, les options, les chemins, le dossier où l'on est ; prédire, taper, comparer avec `ls -R`.
- Dans l'alignement de la fiche : vingt relations typées, chaque notion dans au moins une (section 10).
- **Relation centrale** : « le nom de la destination décide du résultat : absent, il devient le nouveau nom ; un dossier existant, la source s'y range ; un fichier existant, il est remplacé ; et rien ne revient en arrière ». À l'écran : « regarde le nom de la destination avant d'appuyer sur Entrée ».
- Ce que le système produit et qu'aucun élément seul ne contient : dire l'état de l'arborescence avant de taper Entrée, sans souris, sur son poste comme sur un serveur, et lire une ligne copiée avant de la lancer.
- Frontières : dedans, ce qui précède. Dehors : tout ce que liste la section 1 (hors objectif).
- À quoi ça sert dans le métier : un projet est un arbre de dossiers qu'on crée, copie, range et nettoie ; un serveur se pilote au clavier, sans corbeille ; une ligne `rm -rf` copiée d'un forum a déjà effacé des projets ; les tutoriels sont écrits pour Cmd ou pour bash.

Schéma du bloc (règle C08), une chaîne : « l'état de départ et la ligne tapée » → (ce que le shell lit : commande, options, source, destination) → « ce que décide le nom de la destination » → (ce que fait la commande) → « l'état d'arrivée ». Montré rempli dès la première étape pour Yasmine (`cp -Rv site sauvegarde`, `sauvegarde` n'existe pas), rempli une seconde fois au milieu pour un autre cas (`cp -R site sauvegarde` une deuxième fois, à la fin de « Copier »), construit en fin de bloc par l'apprenant pour un cas NOUVEAU (Noah, sur un serveur Linux, `cp -R pages archive`, `archive` existant).

Schéma demandé par le plan pour P3.2 (l'arbre) : réutilisé ici, mais le dessin d'arbre n'est pas repris ; l'état se montre par le listing de `ls -R`, la sortie même que l'apprenant lira sur sa machine.

## 5. Fil rouge : « Le projet imposé »

Une seule histoire. Personnages : Yasmine, 34 ans (la même que B04 à B09), sur son PC, dans la fenêtre d'Ubuntu ; Farid, son ami de formation, sur son Mac ; le formateur. Un seul nouveau personnage, au cas inédit de l'ensemble : Noah, 29 ans. Le formateur impose une arborescence pour le site de la promo (un dossier `site` qui contient `css`, `img` et `index.html`, avec `style.css` dans `css` et `logo.png` dans `img` : trois dossiers, trois fichiers vides) à créer dans un dossier d'atelier, sans `cd`, à vérifier, à sauvegarder, puis à modifier. Gestes qui portent les notions :

1. Yasmine, dans son dossier `atelier`, crée l'arborescence avec `mkdir -p`, `mkdir`, `touch` sans jamais bouger, la lit avec `ls -R`, la sauvegarde avec `cp -Rv` (notions 1 à 7, 11, 24).
2. Farid fait la même sauvegarde deux fois : la seconde se range dans la première (E3). Il copie un fichier dans un dossier existant, sous un nouveau nom, par-dessus un fichier (notions 8 à 10, 22).
3. Yasmine déplace et renomme (`mv`), range avec `..` et `.` (notions 12 à 14, 23).
4. Farid retire un fichier avec `rm`, cherche dans la Corbeille, ne trouve rien (E1) ; Yasmine retire un dossier avec `rm -r` ; le formateur lui montre `-f` (`rm -i` reste hors objectif et n'est jamais interrogé).
5. Yasmine trouve sur un forum une ligne `sudo rm -rf …` pour « faire de la place » : elle la lit avant de la coller (E2, notion 20).
6. Le formateur écrit au tableau les mêmes lignes pour son PC, dans Cmd : `copy`, `move`, `del`, `rmdir /s` ; Yasmine reconnaît ce qui diffère de sa fenêtre d'Ubuntu (E4, notions 25 à 28).
7. Cas inédit (ensemble) : Noah, sur un serveur Linux, tape `cp -R pages archive` alors qu'`archive` existe.

Le fil porte les notions (leçon de B02) : si une notion n'a pas sa place dans l'histoire, l'histoire change, pas la notion.

La machine en attrape une partie ; le reste se relit à l'écriture de chaque écran, cette liste sous les yeux, puis à la relecture de la fiche. 1. **L'écran se résout avec ce qu'il montre.** La règle, la convention, la donnée qu'il faut sont écrites plus haut sur l'écran ou dans l'encadré « Pour lire » ; rien n'est expliqué trois écrans plus loin (B03 : le disque de 931 Go). Une règle montrée sur un seul exemple n'est pas enseignée.
2. **Une consigne, une question.** Le rappel va dans l'encadré ; la question tient en une phrase, un seul temps (« relève, puis juge » fait deux items), et ne souffle pas sa réponse.
3. **Le retour oriente, il ne répond pas.** Une question ou un indice sur la notion ; ni les mots de la bonne option, ni l'attendu, ni la solution. L'encadré « Pour lire » redit une convention, pas la règle que l'exercice vérifie (B03 : « Le vendeur »).
4. **Le mot est celui du modèle**, défini avant d'être employé (« architecture », pas « famille ») ; un mot du métier qui n'est pas défini (tableur, rendu, export, tour) se remplace ou se définit sur place.
5. **Rien de la conception.** Pas de temps ni d'étape numérotés, d'identifiant d'onglet, de nom de classe, d'étiquette de la méthode, de gabarit « [seulement si l'essai est faux] » dans le texte.
6. **La situation revient et l'écran se lit sur un téléphone.** Chaque écran repart de l'histoire du bloc, quatre écrans abstraits d'affilée au plus ; un calcul s'écrit en lignes, pas en ligne continue ; pas une douzaine de noms ou de codes d'un coup (B03, ET8).
7. **Peu de prénoms**, un par cas, le même d'un bout à l'autre du cas (B03 en avait 17).
8. **La charge se compte en écrivant.** Les saisies de l'écran s'ajoutent au total du bloc (B03 : environ 115) ; un exercice qui n'apporte ni notion ni erreur nouvelle se fond dans un autre.
9. **Ce qui se fait hors de la page a son constat** (règle F06), et le mot de l'outil est vérifié (« Enregistreur audio » sous Windows 11 ?).
10. **La grille se recompte avec la fiche** : chaque nombre, chaque citation, la version.

## 9. Contraintes de style et de fond

- Français, tutoiement, accents, aucun tiret cadratin (ni — ni –), phrases courtes, un mot du métier défini avant d'être employé. Un mot, un seul sens du début à la fin : « dossier » partout (jamais « répertoire » sauf le terme officiel « répertoire courant », déjà défini au bloc précédent) ; « arborescence » (le mot de l'objectif) défini une fois sur place : les dossiers et les fichiers rangés les uns dans les autres, vus depuis un dossier ; « dossier d'atelier » pour `atelier` ; « source » et « destination » définis avant leur première question (la source, ce que la commande prend ; la destination, où elle le met) ; « option » (jamais « paramètre » ni « flag ») ; « argument » ; « écraser » défini (remplacer un fichier existant par un autre du même nom, sans rien demander) ; « récursif » comme terme officiel de ce que font `-R` et `-r` (descendre dans les sous-dossiers) ; « corbeille » pour la Corbeille du Finder et celle de l'Explorateur ; « Cmd » défini une fois (l'Invite de commandes de Windows) ; « ligne lue » pour une ligne qu'on ne tape pas ; « état » pour ce qui existe après une commande, défini sur place.
- Le texte de l'apprenant ne dit rien de la conception : pas « étape N », pas « Avant de lire », pas de nom de classe, d'identifiant d'onglet, de temps numéroté.
- Chaque écran se résout avec ce qu'il montre : l'état de départ est imprimé (listing de `ls -R`) sur l'écran, la ligne aussi ; ce que fait chaque option citée est redonné dans un encadré « Pour lire » (une convention, jamais la conclusion de l'exercice).
- Un exercice du cours se pose AVANT le texte qui répond ; ce texte ne paraît qu'une fois l'exercice fini. Une consigne, une question ; le retour d'une option fausse et les coups de pouce sont des questions qui orientent.
- Un écran, une notion, au plus trois mots nouveaux ; quatre écrans abstraits d'affilée au plus ; le projet du formateur ou la sauvegarde de Yasmine et de Farid revient dans chaque étape.
- Une convention se dit d'une seule façon et avec le mot « convention » : un nom d'option en une lettre derrière un tiret, `-p` et `-R` ; « une commande qui réussit ne dit rien » est un fait des commandes UNIX, dit une fois comme tel ; le silence ne veut pas dire « rien n'a changé » : il veut dire « tout s'est bien passé ».
- **Aucune sortie n'est inventée.** Les messages cités sont ceux de la machine de l'auteur (Ubuntu, GNU coreutils 9.4) : `mkdir: cannot create directory 'site/css': No such file or directory`, `touch: cannot touch 'site/doc/notes.txt': No such file or directory`, `cp: -r not specified; omitting directory 'site/css'`, `rm: cannot remove 'site/css2': Is a directory`, `rm: cannot remove 'site/nope': No such file or directory`, `mv: cannot move 'site' to a subdirectory of itself, 'site/css/site'`, `bash: line 1: copy: command not found` (la fiche cite « command not found »). Le reste est dit en mots, sans citer (« une phrase d'erreur »).
- Exact sur les faits (vérifiés sur Ubuntu) :
  - `mkdir site/css` échoue si `site` n'existe pas ; `mkdir -p site/css` crée `site` puis `css`, ne dit rien, et ne se plaint pas si le dossier existe (code 0) ; `mkdir site/css` sur un dossier existant échoue (« File exists »).
  - `touch site/index.html` crée un fichier vide ; sur un fichier existant, ne change que sa date ; `touch site/doc/notes.txt` échoue si `doc` n'existe pas.
  - `ls -R site` : « site: » puis les noms, une ligne vide, « site/css: » puis ses noms, et ainsi de suite, par ordre alphabétique ; un dossier vide n'a que son titre ; un nom qui commence par un point n'y est pas sans `-a`. Dans un terminal, `ls` range les noms côte à côte quand ils tiennent ; la fiche imprime les listings ainsi, et dit que la mise en colonnes varie avec la largeur de la fenêtre. Les noms de l'atelier sont en minuscules, sans point sauf l'extension, pour que l'ordre soit le même sous les deux systèmes.
  - `cp site/index.html site/accueil.html` : copie sous un nouveau nom ; `cp site/index.html site/img` : copie dans le dossier ; sur un fichier existant, l'écrase sans rien dire. `cp site/css site/css2` : échoue, rien ne change. `cp -R site/css site/css2` : `css2` est une copie de `css` si `css2` n'existe pas ; si `css2` existe, la copie est `css2/css`. `cp -Rv site sauvegarde` écrit une ligne par élément copié, dossiers compris, six lignes ici, sous la forme `'site/css' -> 'sauvegarde/css'` ; la seconde fois, les destinations sont `sauvegarde/site`, `sauvegarde/site/css`, etc.
  - `mv` : renomme si la destination n'existe pas ; range dedans si c'est un dossier existant ; remplace un fichier existant sans rien dire (la source disparaît, la destination reste) ; `mv site site/css` échoue (« a subdirectory of itself »). Un dossier se déplace avec son contenu, sans option. `mv fichier dossier-absent/` : la fiche n'emploie pas la barre finale (un dossier source avec barre finale est renommé : piège évité).
  - `rm site/css2` sur un dossier : échoue. `rm -r site/css2` : le retire avec tout son contenu, sans rien dire. `rm -f site/nope` : ne dit rien, code 0 ; `rm site/nope` : « No such file or directory ». `rm -i` (demande avant chaque suppression) est hors objectif : la fiche le nomme en une phrase de contraste avec `-f` et ne l'interroge jamais.
  - Dans bash, `copy` : « command not found » ; `del` et `move` de même.
  - Les dix lignes de l'atelier, jouées dans cet ordre sur `site` et `sauvegarde` (voir section 6) : après la dixième, `site` contient `css` (`home.html`, `style.css`) et `img` (`index.html`, `logo.png`), plus rien d'autre ; `index.html` n'existe plus à la racine du site.
- **Faits non vérifiables sur cette machine** (à vérifier sur machine ; la page ne s'appuie que sur le comportement connu et stable, jamais sur un texte exact de Mac ou de Windows) :
  - macOS : `mkdir -p`, `touch`, `ls -R`, `cp -R`, `cp -Rv`, `mv`, `rm`, `rm -r`, `rm -f` existent et agissent comme sous Linux pour les cas du bloc (destination absente ou dossier existant). `cp -Rv` y écrit encore une ligne par élément copié, sans les apostrophes (`site/css -> sauvegarde/css`) : la fiche ne dépend ni du texte ni du nombre exact de lignes, elle les compte seulement sous Ubuntu (« six lignes sous Ubuntu »). Le message de `cp` sans `-R` y est une autre phrase qui dit que le dossier n'est pas copié : la fiche cite le message d'Ubuntu et dit que celui d'un Mac est autre. `rm` ne passe pas par la Corbeille du Finder (comportement connu). Les noms ne changent pas de casse dans l'atelier. `~/Documents`, `~/Desktop` et `~/Downloads` sont évités (le dossier d'atelier est `~/atelier`).
  - Windows : `copy` ne copie pas les sous-dossiers (`xcopy /E /I` le fait, nommé sans question) ; `del` retire des fichiers, pas un dossier ; `rmdir /s` retire le dossier et son contenu et demande une confirmation sauf avec `/q` (la fiche ne cite pas la phrase) ; ni `del` ni `rmdir /s` ne passent par la Corbeille ; `move` renomme ou range comme `mv` ; Cmd ne connaît pas `cp`, `mv`, `rm`, `ls`. L'inverse (une ligne de Cmd tapée dans bash) : « command not found » pour `copy`, `move`, `del` (vérifié pour bash).
  - Faux ami, volontairement écarté : `rmdir` existe sous Ubuntu (il retire un dossier vide), donc `rmdir /s site` n'y échoue pas toujours de la même façon ; la fiche ne fait jamais taper ni prédire cette ligne dans bash.
- Accessibilité : chaque listing est un `<pre class="listing">` avec son `data-lecture` ; chaque ligne lue se distingue des lignes tapées (« Ligne lue, à ne pas taper ») ; aucun outil réservé à la souris ; rien ne déborde à 390 px.
- Poids : moins de 5 Mo.

## 10. Les notions à couvrir

Les 30 notions de la section 6 du contrôle du plan, regroupées en 29 lignes du tableau (N29, plusieurs noms à la fois, est ajoutée en version 3 pour que `mkdir -p a b` et `touch a b c` soient enseignés avant d'être demandés) (en version 4, `rm -i` sort de l'objectif : N19 et N28 disparaissent de l'alignement et leurs relations avec elles ; il reste 27 notions et 20 relations) (les notions 1 et 24 forment N1, 26 et 27 forment N25, la 25 est N24, la 28 est N26, la 29 est N27, la 30 est N28).

Créer sans bouger : N1 toute commande de manipulation prend un chemin évalué depuis le répertoire courant et ne change pas de dossier, donc on peut tout faire sans `cd` ; l'atelier se fait dans un dossier créé pour cela, où l'on ne supprime que ce que l'on y a créé (notions 1 et 24) ; N2 les commandes qui créent, copient, déplacent ou retirent ne disent rien quand elles réussissent (`pwd`, `ls`, `cp -v` répondent), un message d'erreur veut dire que la ligne n'a rien changé pour le nom refusé ; N3 `mkdir nom` crée un dossier dans le dossier visé et échoue si le dossier parent n'existe pas ; N4 `mkdir -p chemin` crée tous les dossiers manquants du chemin et ne dit rien si le dossier existe déjà ; N5 `touch nom` crée un fichier vide, ne change que sa date s'il existe, et échoue si le dossier parent n'existe pas ; N6 `ls -R dossier` affiche le contenu de chaque sous-dossier sous un titre `dossier:`, un dossier vide n'a que son titre, les noms cachés n'y sont pas sans `-a` ; N7 vérifier une arborescence, c'est comparer la sortie de `ls -R` à l'arborescence imposée, nom par nom et casse comprise.

Copier : N8 `cp source destination` copie un fichier, l'écrase sans question si la destination est un fichier existant ; N9 `cp` seul refuse un dossier, `cp -R` copie un dossier avec tout son contenu ; N10 `cp -R foo bar` donne `bar` (copie de `foo`) si `bar` n'existe pas, `bar/foo` si `bar` existe ; N11 `-v` fait écrire à `cp` chaque copie faite, et `cp -Rv dossier sauvegarde` sauvegarde une arborescence vers un nom qui n'existe pas encore ; N28 la sortie de `cp -Rv` et le message d'échec de `cp` sans `-R` diffèrent entre Ubuntu et un Mac.

Déplacer : N12 `mv source destination` renomme si la destination n'existe pas, range dedans si c'est un dossier existant ; N13 `mv` écrase un fichier existant sans question et refuse de déplacer un dossier dans lui-même ; N14 `mv` d'un fichier ou d'un dossier déplace l'élément avec tout son contenu : il n'y a pas d'option `-R` pour `mv` ; N23 `.` et `..` servent d'arguments de manipulation (`cp fichier .`, `mv fichier ..`).

Supprimer : N15 `rm fichier` supprime un fichier, sans corbeille ni retour ; N16 `rm` seul refuse un dossier, `rm -r dossier` supprime le dossier et tout ce qu'il contient ; N17 `-f` supprime sans demander et sans se plaindre d'un nom inexistant, donc `rm -rf` détruit un dossier sans rien dire ; N18 `sudo` devant `rm` supprime aussi ce que l'utilisateur n'a pas le droit de supprimer ; N20 avant de lancer une ligne `rm -r` copiée d'ailleurs, lire dans l'ordre : la commande, les options, les chemins, le dossier où l'on est.

Prédire : N21 prédire une commande, c'est dire l'état de l'arborescence après elle (ce qui existe, sous quel nom, dans quel dossier) ; l'échec la laisse telle quelle ; N22 la commande se prédit d'après le nom de la destination : existante ou non, fichier ou dossier.

Cmd : N24 Cmd écrit les chemins avec des antislashs et les options avec `/` ; `cp`, `mv`, `rm`, `ls` y sont inconnues, `copy`, `del`, `move` le sont dans bash (notion 25 du contrôle) ; N25 équivalents `copy` (`xcopy /E /I` pour `cp -R`), `move`, `del` (fichiers), `rmdir /s` (dossier et contenu) ; `del` ne supprime pas un dossier et `copy` ne copie pas les sous-dossiers (notions 26 et 27) ; N26 sur un Mac, Cmd n'existe pas : les équivalents se lisent sur des lignes imprimées, sans les taper (notion 28).

Aisance : N27 dix prédictions de l'état d'un dossier justes sur dix, sur plusieurs jours, et l'arborescence de six éléments créée puis vérifiée en moins d'une minute, de mémoire, puis sauvegardée avec le temps noté (notion 29).
