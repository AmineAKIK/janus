## 2. L'objectif, mot pour mot

Windows : dire ce qu'est un shell et en quoi Cmd et l'invite d'Ubuntu diffèrent ; ouvrir un terminal en administrateur, installer WSL 2 + Ubuntu (machine virtuelle légère avec un vrai noyau Linux), créer l'utilisateur Linux, prouver la version avec `wsl -l -v` (VERSION 2) et distinguer `wsl --update` de `apt upgrade` ; diagnostiquer un échec d'installation lié à la virtualisation (BIOS/UEFI, fonctionnalité « Plateforme de machine virtuelle », Hyper-V complet inutile). macOS : dire que le système est déjà UNIX, installer Homebrew par la commande officielle de brew.sh (curl puis bash, source officielle seulement), l'ajouter au PATH par les lignes « Next steps » et le prouver avec `which brew` dans un nouveau terminal. Dans les deux cas : dire ce qu'est un paquet, un dépôt, une dépendance ; mettre à jour la liste puis les paquets (`apt update` contre `apt upgrade`, `brew update` contre `brew upgrade`) ; installer, lister, retirer (`apt install`, `brew install`, `brew list`, `brew uninstall`) et vérifier `tree` ; dire le rôle de `sudo` ; enchaîner deux commandes avec `&&`.

## 3. Erreurs critiques (en phrases d'apprenant)

- E1 « Une fois WSL installé, mes commandes Linux marchent dans mon Invite de commandes (Cmd). » Le shell de Windows et celui d'Ubuntu sont deux programmes différents, dans deux fenêtres.
- E2 « `sudo apt update` installe les mises à jour. » `update` actualise la liste des paquets disponibles ; `upgrade` installe.
- E3 « Homebrew installe Linux sur mon Mac. » Le Mac est déjà UNIX ; Homebrew lui ajoute des outils.
- E4 « Je recopie la commande de Homebrew d'un forum ou d'un site qui lui ressemble. » Le script s'exécute avec nos droits : on le recopie de brew.sh seulement.

Chaque erreur a un item de pratique qui la révèle (`data-erreur` sur l'option ou la ligne), un retour qui NOMME l'élément du modèle en cause, une étape d'explication qui la montre, un essai de l'intuition, et au moins une différée qui la touche (le bilan ne peut sinon pas la refermer).

## 4. Le modèle du bloc

Système enseigné : **pour travailler comme un développeur, il faut un shell UNIX et un gestionnaire de paquets qui lui ajoute des outils. Windows n'est pas UNIX : WSL 2 fait tourner un vrai noyau Linux (Ubuntu) dans une machine virtuelle légère, ce qui demande la virtualisation du processeur, et son shell est distinct de Cmd. Le Mac est déjà UNIX : Homebrew, installé par un script officiel et ajouté au PATH, lui apporte le gestionnaire de paquets. Dans les deux cas, le gestionnaire interroge un dépôt : on actualise d'abord sa liste (update), puis on installe ou on met à jour les paquets (install, upgrade), avec les droits qu'il faut (sudo).**

Éléments : terminal, shell (Cmd, PowerShell, bash, zsh), invite, UNIX, Linux, distribution (Ubuntu), noyau, WSL 2, machine virtuelle légère, virtualisation du processeur, BIOS/UEFI, Plateforme de machine virtuelle, Hyper-V, terminal administrateur, utilisateur Linux, `wsl --install`, `wsl -l -v`, `wsl --update`, Homebrew, brew.sh, script d'installation (curl, bash), PATH, lignes « Next steps », `which`, paquet, dépôt, dépendance, `apt`, `brew`, `sudo`, `&&`, `tree`.

Relations (types pour la conception ; à l'écran tout est dit en mots) :

- Composition : Ubuntu est une distribution, un noyau Linux et des outils réunis ; WSL 2 = une machine virtuelle légère + un vrai noyau Linux + une distribution.
- Condition : la virtualisation activée dans le BIOS/UEFI, puis la fonctionnalité « Plateforme de machine virtuelle », puis `wsl --install` ; sans le PATH à jour, le shell ne trouve pas `brew` ; sans la liste à jour (`update`), `upgrade` et `install` travaillent sur une liste périmée.
- Séquence : terminal administrateur, `wsl --install`, redémarrage, utilisateur Linux, `wsl -l -v` ; brew.sh, commande, « Next steps », nouveau terminal, `which brew` ; `update` puis `upgrade`.
- Opposition : Cmd contre l'invite d'Ubuntu ; `apt update` contre `apt upgrade` (et `brew update` contre `brew upgrade`) ; `wsl --update` contre `apt upgrade` ; Windows (pas UNIX) contre macOS (déjà UNIX) ; WSL 1 contre WSL 2 ; Hyper-V complet contre Plateforme de machine virtuelle ; terminal contre shell ; paquet réseau (blocs d'avant) contre paquet logiciel.
- Équivalence : `apt` et `brew` jouent le même rôle (install, update, upgrade, remove ou uninstall) sur deux systèmes ; le terminal administrateur de Windows et `sudo` demandent tous deux des droits d'administrateur.
- Cause : un script lancé avec nos droits agit avec nos droits, donc on ne l'exécute que d'une source officielle ; le shell cherche une commande dans les dossiers du PATH, donc `brew` n'est trouvé que si son dossier y est.
- **Relation centrale** : « le bon shell d'abord (UNIX), puis le gestionnaire de paquets : la liste se met à jour avant les paquets, et ce qui change le système demande des droits ». À l'écran : « pour installer un outil, on a d'abord un shell UNIX, puis on actualise la liste, puis on installe ».
- Ce que le système produit et qu'aucun élément seul ne contient : un poste où `tree` (puis tout outil à venir) s'installe en une ligne, de la même façon sur Windows et sur Mac.
- Frontières : dedans, ce qui précède. Dehors : se déplacer et manipuler les fichiers (blocs suivants), `~` et `/mnt/c`, XAMPP, VS Code, GitHub et ses offres, la sécurité des mises à jour (la partie suivante).
- À quoi ça sert dans le métier : PHP, Git, tout outil de la suite s'installe et se lance dans un shell UNIX ; un serveur en production tourne sous Linux ; savoir ce que fait chaque commande avant de la lancer évite d'abîmer son poste.

Schéma du bloc (règle C08) : le PC avec Windows et, à côté, une machine virtuelle légère qui contient WSL 2 (noyau Linux) et Ubuntu, et à côté le Mac « déjà UNIX » avec Homebrew comme boutique d'outils. Montré rempli pour Yasmine et Farid au début, rempli une seconde fois au milieu pour d'autres cas (la chaîne de Yasmine à la fin d'ET5, celle de Farid à la fin d'ET7, de la même forme que celle de Noah), construit en fin de bloc par l'apprenant pour un cas NOUVEAU (Noah).

## 5. Fil rouge : « Deux postes, un même outil »

Une seule histoire. Personnages (peu de prénoms, chacun garde son âge et son statut) : Yasmine, 34 ans (la même que B04 à B07), sur son PC Windows ; Farid, son ami de formation, sur son Mac ; le formateur. Un seul nouveau personnage, au cas inédit de l'ensemble : Noah, sous Windows. Le formateur leur annonce que la suite de la formation se fait dans un shell UNIX et qu'ils commenceront par installer l'outil `tree`. Gestes qui portent les notions :

1. Yasmine ouvre un terminal en administrateur, tape `wsl --install`, redémarre, crée son utilisateur, vérifie `wsl -l -v`, puis installe `tree` dans la fenêtre d'Ubuntu (le shell, le terminal administrateur, WSL 2, l'utilisateur, `sudo`, `apt`, `update` contre `upgrade`).
2. Elle oublie un jour et tape sa commande Ubuntu dans Cmd (E1) ; elle lit `wsl --update` et `apt upgrade` (deux mises à jour).
3. Une camarade reçoit l'erreur 0x80370102 : la virtualisation, la fonctionnalité Windows, Hyper-V inutile (transfert du plan).
4. Farid ouvre son Terminal, recopie la commande de brew.sh, lit « Next steps », ouvre un nouveau terminal, tape `which brew` (le Mac déjà UNIX, curl et bash, le PATH, E3 et E4).
5. Tous deux : `update`, `upgrade`, `install`, `list`, `uninstall`, `tree` ; `&&` enchaîne deux commandes.
6. Cas inédit (ensemble) : Noah, sous Windows, veut `htop` dans un shell UNIX (la seconde plainte de Farid, le PATH, a été fondue dans l'item PR1-5 et la carte B08-K3).

Le fil porte les notions (leçon de B02) : si une notion n'a pas sa place dans l'histoire, l'histoire change, pas la notion.

## 9. Contraintes de style et de fond

- Français, tutoiement, accents, aucun tiret cadratin (— ni –), phrases courtes, un mot du métier défini avant d'être employé (shell, invite, noyau, distribution, machine virtuelle, virtualisation, hyperviseur, PATH, paquet, dépôt, dépendance, sudo, administrateur). Un mot, un seul sens du début à la fin : **« paquet » désigne ici un logiciel installable** (et pas le paquet réseau de B05 et B06 : une phrase le dit, une fois, à l'endroit où le mot paraît) ; « terminal » la fenêtre, « shell » le programme qui lit les commandes ; « administrateur » le niveau de droits ; « liste » la liste des paquets que le gestionnaire connaît ; « mise à jour » ne s'emploie jamais seul là où `update` et `upgrade` se distinguent.
- Le texte de l'apprenant ne dit rien de la conception : pas « étape N », pas « Avant de lire », pas de nom de classe, d'identifiant d'onglet, de temps numéroté.
- Chaque écran se résout avec ce qu'il montre : la donnée, la règle, la convention interrogée sont redonnées sur place dans un encadré « Pour lire » titré (une définition ou une propriété littérale d'un terme, jamais la conclusion de l'exercice). Aucun « plus haut », « comme avant » : ce que fait chaque commande est redonné à chaque exercice qui l'emploie.
- Une consigne, une question ; la question ne souffle pas sa réponse ; le retour d'une option fausse et les deux premiers coups de pouce orientent par une question, sans les mots de la bonne option.
- Quatre écrans abstraits d'affilée au plus ; Yasmine ou Farid revient dans chaque étape ; un exercice vérifié tous les trois ou quatre écrans de définition.
- Un écran, une notion, au plus trois mots nouveaux (shell, terminal, invite : trois ; Linux, UNIX, Ubuntu, noyau : deux écrans).
- Les sorties de terminal sont **fournies** (`<pre class="listing">` avec `data-lecture`), fictives, sur des noms d'utilisateur et des chemins d'exemple. Aucune sortie ne ment : ce qu'une commande affiche réellement est vérifié (sources : Microsoft Learn pour WSL, brew.sh pour Homebrew), et quand l'affichage dépend de la langue ou de la version (titres des colonnes de `wsl -l -v`, texte de « Next steps »), la fiche le dit.
- Aucun message d'erreur n'est inventé : pour 0x80370102, la fiche donne le code, dit qu'il signale une virtualisation indisponible et reprend le sens du message (activer la fonctionnalité « Plateforme de machine virtuelle » et vérifier la virtualisation dans le BIOS), sans citer une phrase française qu'elle ne peut pas garantir.
- Exact sur les faits :
  - `wsl --install` installe WSL et la distribution Ubuntu par défaut, demande un redémarrage ; au premier lancement d'Ubuntu, il demande un nom d'utilisateur puis un mot de passe, qui ne s'affiche pas quand on le tape ; cet utilisateur est distinct du compte Windows. Quand WSL est déjà installé, `wsl --install` affiche son aide : `wsl --install -d Ubuntu` installe la distribution (coup de pouce de l'atelier).
  - `wsl -l -v` (`--list --verbose`) liste les distributions avec leur état et leur version ; les titres des colonnes suivent la langue de Windows ; VERSION 2 prouve WSL 2 ; `wsl --set-version Ubuntu 2` convertit une distribution en VERSION 1 (coup de pouce seulement).
  - `wsl --update` met à jour le composant WSL de Windows (son noyau Linux), pas les paquets d'Ubuntu ; `apt upgrade` met à jour les paquets d'Ubuntu.
  - WSL 2 demande la virtualisation matérielle du processeur, activée dans le BIOS/UEFI, et la fonctionnalité Windows « Plateforme de machine virtuelle » ; `wsl --install` l'active. Hyper-V complet (le rôle et ses outils) n'est pas nécessaire : Windows Famille n'a pas Hyper-V et peut faire tourner WSL 2.
  - Sous Ubuntu : `sudo apt update` actualise la liste, ne change aucun paquet installé ; `sudo apt upgrade` installe les versions plus récentes des paquets déjà installés ; `sudo apt install tree` ajoute un paquet et ses dépendances ; `sudo apt remove tree` le retire.
  - Homebrew : adresse officielle brew.sh ; la commande est `/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"` ; l'installateur demande le mot de passe de l'utilisateur et la touche Entrée pour continuer, puis finit par « Next steps » ; sur Apple silicon, Homebrew est dans `/opt/homebrew` et les lignes proposées l'ajoutent au PATH (`eval "$(/opt/homebrew/bin/brew shellenv)"`, écrit dans le fichier `.zprofile` que zsh lit à chaque nouveau terminal) ; `brew` se lance sans `sudo` ; `which brew` rend `/opt/homebrew/bin/brew`, et zsh écrit « brew not found » quand `brew` n'est pas dans le PATH.
  - `brew update` met à jour Homebrew et sa liste ; `brew upgrade` met à jour les paquets installés ; `brew list` liste les paquets installés ; `brew uninstall tree` retire.
  - `tree --version` et `which tree` vérifient l'installation (`/usr/bin/tree` sous Ubuntu, `/opt/homebrew/bin/tree` sous Apple silicon).
- Accessibilité : chaque image ou schéma a sa description et son `data-lecture` ; aucun outil réservé à la souris ; rien ne déborde à 390 px ; les sorties de terminal sont des `<pre class="listing">` avec leur `data-lecture`.
- Poids : moins de 5 Mo (SVG et HTML, pas d'image lourde).

## 10. Les 21 notions à couvrir

Le poste et les mots :

1. Un shell est le programme qui lit les commandes tapées dans un terminal et les exécute ; le terminal n'est que la fenêtre.
2. Linux et macOS sont des systèmes de la famille UNIX ; Ubuntu est une distribution Linux (un noyau et des outils réunis).
3. Le noyau est la partie du système qui parle au matériel.
4. Cmd (Windows) et l'invite d'Ubuntu sont deux shells distincts : une commande Linux tapée dans Cmd échoue, et on reconnaît le shell à son invite.

Windows : WSL 2 5. WSL 2 fait tourner un vrai noyau Linux dans une machine virtuelle légère sous Windows ; la colonne VERSION distingue WSL 1 de WSL 2. 6. La virtualisation doit être activée dans le BIOS/UEFI (lue au Gestionnaire des tâches) et la fonctionnalité « Plateforme de machine virtuelle » présente ; Hyper-V complet n'est pas nécessaire. 7. Une erreur d'installation du type 0x80370102 se traite dans l'ordre : virtualisation dans le BIOS/UEFI, fonctionnalité Windows, redémarrage. 8. Un terminal se lance en administrateur pour `wsl --install`, parce que l'installation modifie le système. 9. `wsl --install` installe WSL et Ubuntu, demande un redémarrage, puis la création de l'utilisateur Linux (nom et mot de passe), distinct du compte Windows ; le mot de passe ne s'affiche pas à la frappe. 10. `wsl -l -v` liste les distributions avec leur état et leur VERSION ; Ubuntu en VERSION 2 prouve l'installation. 11. `wsl --update` met à jour le composant WSL de Windows, `apt upgrade` les paquets d'Ubuntu.

macOS : Homebrew 12. macOS est déjà UNIX ; Homebrew est un gestionnaire de paquets qui lui ajoute des outils et n'installe pas Linux. 13. L'installation de Homebrew passe par une commande qui télécharge un script avec curl et l'exécute avec bash ; on ne la copie que de brew.sh, parce que le script s'exécute avec nos droits. 14. Le PATH est la liste des dossiers où le shell cherche les commandes ; sur Apple silicon les lignes « Next steps » ajoutent `/opt/homebrew` au PATH. 15. `which` donne l'emplacement d'une commande, ou rien (« not found ») si le shell ne la trouve pas ; `which brew` dans un nouveau terminal prouve l'installation.

Paquets et droits 16. Un paquet est ici un logiciel installable (autre sens que le paquet réseau) ; un dépôt est le serveur qui les tient ; une dépendance est un autre paquet dont il a besoin. 17. `apt update` actualise la liste des paquets disponibles et n'installe rien ; `apt upgrade` installe les versions plus récentes des paquets déjà installés ; `apt install` ajoute un paquet. 18. `brew update` actualise Homebrew et sa liste ; `brew upgrade` met à jour les paquets installés ; `brew install`, `brew list` et `brew uninstall` installent, listent, retirent. 19. `sudo` exécute une commande avec les droits d'administrateur après avoir demandé le mot de passe de l'utilisateur ; on ne le met pas devant une commande qu'on ne comprend pas. 20. `tree` s'installe par le gestionnaire de paquets (apt ou brew) et se vérifie avec `which tree` ou `tree --version`. 21. `&&` enchaîne deux commandes : la seconde ne part que si la première a réussi.

Automatismes à couvrir : `sudo apt update && sudo apt upgrade`, `wsl -l -v`, `brew install` et `brew list` de mémoire.

## 11. Les classes de défaut de B01 à B07 (à ne pas reproduire)

1. **B01 (18 et 21 octobre)** : question dont la convention n'est pas redonnée ; explication demandée pour ce que l'écran montre ; état calculé par la page au lieu du serveur ; un champ sans `inputmode` ; chaque erreur critique sans item qui la révèle ; ne jamais retirer une aide avant une réussite seule.
2. **B02 (25 octobre)** : écran qui renvoie à un autre (« le thermostat corrigé », « la chaîne ») ; consignes empilées de rappels ; fil rouge qui disparaît (13 écrans abstraits d'affilée) ; règle dite six fois ; prénom à deux âges ; données écrites en variables ; question qui présuppose sa réponse (« diffèrent », « pourquoi une seule ») ; schéma de fin refait de mémoire au lieu d'être construit sur un cas nouveau.
3. **B03 (29 octobre et 1er novembre)** : un geste retiré parce que la page ne le voit pas (HWMonitor) ; le retour et les coups de pouce qui recopient la bonne option ; « Pour lire » qui donne la règle (« Le vendeur ») ; donnée expliquée trois écrans plus loin ; 17 prénoms ; 115 saisies ; étiquettes de conception dans le texte (« temps 2 à 4 », « l'accroche »).
4. **B04 et B05** : un mot à deux sens (« opérateur », « transport », « connexion », « client ») ; une image fausse ou sans limite ; un exemple qui prête à une technique un comportement faux ; cinq écrans de définition d'affilée ; 94 saisies et 64 écrans ; cartes de correspondance.
5. **B06 (13 h 30, 13 manches)** : une question qui demande trois choses ; une réponse écrite dans l'écran avant sa question ; une explication de variante identique à celle de son item ; un appareil cité dans un coup de pouce et absent de l'énoncé ; une adresse non qualifiée dans sa phrase ; les comptes du texte de conception confrontés à la page ; le lecteur qui n'a pas accès à ce que le texte demande de regarder.
6. **B07 (v1 à v3)** : charge (65 écrans, 120 saisies) ; décrochages dans les écrans de définition longs (ET5 et ET6 allégés) ; îles (le cadenas, le deep web) ; un atelier dont une étape dépend de la réponse d'un site du jour (un second cas est prévu) ; une même notion dite plusieurs fois ; une grille qui dit plus que la fiche.
7. **Spécifique à ce bloc** : un message d'erreur ou une sortie de terminal inventés (rien n'est cité qui ne soit vérifiable) ; une commande Windows et une commande Linux confondues dans un même exemple ; un geste réservé à un système sans critère pour l'autre ; « paquet » pris pour un paquet réseau ; une procédure d'installation lue sans être faite (F06).
