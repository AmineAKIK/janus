## 2. L'objectif, mot pour mot

Depuis le terminal, code . ouvre un dossier comme projet ; squelette HTML par Emmet ; aperçu Live Preview ; terminal intégré ; expliquer éditeur contre IDE et choisir entre VS Code et un IDE JetBrains pour un besoin donné, licence et architecture comprises ; dire qu'une extension de langage n'installe pas le langage, que la synchronisation des paramètres transporte les réglages et pas les projets, que VS Code n'est pas Visual Studio et que le code généré par une IA n'est pas une preuve.

(Décision d'Amine : l'objectif est élargi aux quatre erreurs critiques que l'objectif de départ ne nommait pas. L'erreur « PhpStorm a une édition Community » reste portée par « licence comprise ».)

## 3. Erreurs critiques (celles du plan, en phrases d'apprenant, dans l'ordre du plan)

- E1 « Visual Studio, c'est VS Code : je télécharge celui qui s'appelle Visual Studio. » Confondre VS Code et Visual Studio : deux produits de Microsoft, un éditeur léger et gratuit, et un IDE à part, avec son installateur, ses éditions et sa licence.
- E2 « J'ai installé l'extension PHP (ou JavaScript), donc PHP (ou Node) est installé. » Croire qu'une extension de langage installe le langage : elle ajoute la coloration et l'aide à l'écriture ; le langage s'installe sur la machine, à part.
- E3 « Ma synchronisation est activée : mes projets sont sauvegardés. » Croire que la synchronisation des paramètres sauvegarde les projets : elle transporte les réglages, les raccourcis et les extensions, jamais les dossiers de projet.
- E4 « Je prends PhpStorm Community, gratuit, pour mon travail. » Croire que PhpStorm a une édition Community : il n'en a pas ; ses voies gratuites sont la licence étudiante et le mode non commercial, qui n'autorisent pas un travail payé.
- E5 « L'IA m'a écrit la page, donc je sais la faire. » Laisser une IA générer le code pendant l'apprentissage : le code généré n'est pas une preuve de ce qu'on sait faire (règle P03) ; pendant l'apprentissage, on tape soi-même.

Chaque erreur a une étape d'explication qui la montre (E1 et E4 : « Choisir son outil » ; E2 et E3 : « Éditeur, IDE et extensions » ; E5 : « Taper toi-même »), un essai de l'intuition (E1, E3, E4, E5 ; E2 est parié dans la perception, « Ton pari », et repris en fin de bloc), un item de pratique qui la révèle (`data-erreur`), un retour qui nomme l'élément du modèle en cause et au moins une différée qui la touche.

## 4. Le modèle du bloc

Système enseigné : **un éditeur ouvre un dossier de ta machine comme projet ; tout ce qu'il fait a une source : lui-même (Emmet, le terminal intégré, la palette de commandes), une extension qu'on lui ajoute (Live Preview, une extension de langage) ou la machine sur laquelle il tourne (le langage installé, son architecture, ses dossiers). Installer l'une n'installe pas les autres. On choisit l'outil d'après le besoin, la licence et l'architecture de la machine.**

Éléments : machine (système, architecture x64 ou ARM64, langages installés), fenêtre de commandes (terminal), commande `code`, PATH, dossier courant `.`, projet (dossier ouvert), éditeur (VS Code), palette de commandes, Emmet, extension (Live Preview, extension de langage), terminal intégré et son profil (bash, Cmd, PowerShell), synchronisation des paramètres, IDE (Visual Studio, IDE JetBrains : PhpStorm, WebStorm, PyCharm, IntelliJ IDEA), licence (gratuite, payante, étudiante, mode non commercial, Community), code généré par une IA.

Relations (types pour la conception ; à l'écran tout est dit en mots) :

- Composition : la fenêtre d'un éditeur = une liste du projet, des fichiers ouverts, un terminal intégré, une palette ; un IDE = un éditeur + débogueur + analyse + outils du langage.
- Catégorie : Live Preview et une extension de langage sont deux sortes d'extensions ; PhpStorm, WebStorm, PyCharm, IntelliJ IDEA sont des IDE de JetBrains ; bash, Cmd et PowerShell sont des profils de terminal ; x64 et ARM64 sont deux architectures.
- Opposition : éditeur contre IDE ; VS Code contre Visual Studio ; extension contre langage installé ; réglages contre projets (synchronisation) ; abréviation fixe d'Emmet contre code inventé par une IA ; gratuit contre payant ; licence étudiante contre usage commercial.
- Condition : `code .` ne marche que si la commande `code` est dans le PATH et si la fenêtre est dans le bon dossier ; un installateur ne marche que s'il est de l'architecture de la machine ; Emmet n'agit que dans un fichier reconnu comme HTML ; l'aperçu n'existe qu'une fois l'extension installée ; un langage ne s'exécute que s'il est installé sur la machine ; le choix d'un IDE dépend du langage du besoin, de la licence et de la machine.
- Équivalence : `.` désigne le dossier courant ; la palette de commandes lance une commande par son nom.
- Cause : `code .` ouvre le dossier courant comme projet ; la commande de la palette « Shell Command » met `code` dans le PATH (macOS) ; le terminal intégré s'ouvre dans le dossier du projet, donc `pwd` y répond ce dossier.
- Séquence : installer, vérifier avec `code --version`, se placer dans le dossier, `code .`, ouvrir le fichier, Emmet, Live Preview, terminal intégré.
- **Relation centrale** : « chaque fonction a une source distincte (l'éditeur, une extension, la machine) : une extension ne remplace pas ce que la machine doit installer ». À l'écran : « avant de dire qu'il marche, demande d'où ça vient ».
- Ce que le système produit et qu'aucun élément seul ne contient : dire, pour un outil, ce qui vient de l'éditeur, de son extension ou de la machine, donc ce qu'il reste à installer ; et choisir un outil pour un besoin sans confondre deux produits qui se ressemblent par le nom.
- Frontières : dedans, ce qui précède. Dehors : tout ce que liste la section 1 (hors objectif).
- À quoi ça sert dans le métier : l'éditeur est l'outil où l'on passe la journée ; ouvrir un projet, avoir un squelette, voir son travail et garder un terminal sous la main se font sans quitter la fenêtre ; une extension ou une synchronisation mal comprise coûte une journée ; le choix d'un outil engage une licence ; et le bloc suivant ouvre un fichier `index.php` dans cet éditeur.

Schéma du bloc (règle C08), une chaîne : « le besoin et la machine de départ » → (ce que l'éditeur et son extension apportent) → « ce que la machine a ou n'a pas » → (ce que la machine répond) → « ce qu'il reste à faire ». Montré rempli dès la première étape pour Yasmine (`code .`, Emmet, Live Preview et terminal intégré, en deux déroulés) ; le cas du pari (extension de langage PHP) est repris et corrigé en fin de bloc ; le schéma est construit par l'apprenant pour un cas nouveau : Noah (29 ans), sur un PC ARM64, installe une extension de langage JavaScript, puis tape `node -v` dans le terminal intégré et obtient « command not found » (le langage n'est pas installé : une extension n'installe pas le langage ; PHP est le cas du pari, JavaScript est celui du schéma).

## 5. Fil rouge : « Le projet de Yasmine »

Une seule histoire. Personnages : Yasmine, 34 ans (la même que B04 à B10), sur son PC, dans la fenêtre d'Ubuntu ; Farid, son ami de formation, sur son Mac ; Noah, 29 ans, pour le cas nouveau de l'ensemble et quelques cartes (comme dans B10). Le formateur demande d'écrire dans le dossier `site` créé au bloc précédent (un `index.html` vide) et de voir le résultat. Gestes qui portent les notions :

1. Yasmine ouvre le dossier `site` dans l'éditeur avec `code .` (notions N1, N2, N14).
2. Elle obtient le squelette HTML par Emmet (N3) et installe Live Preview pour voir la page (N4).
3. Elle ouvre le terminal intégré et choisit son profil (N5).
4. Elle veut écrire du PHP, installe l'extension, et découvre ce que l'extension n'a pas installé (N7) ; Farid active la synchronisation de ses réglages et croit ses projets sauvegardés (N8).
5. Le formateur lui demande de choisir entre VS Code et un IDE de JetBrains : Visual Studio, PhpStorm, la licence, le processeur (N6, N9 à N12) ; elle demande à une IA d'écrire sa page, et le formateur dit pourquoi elle la tape elle-même (N13).

Le fil porte les notions : si une notion n'a pas sa place dans l'histoire, l'histoire change, pas la notion.

2. **Carte** « Où tu es » : la partie, ce que l'éditeur apporte, ce qu'on sait déjà (une phrase), ce qu'on saura faire, sans nommer les pièges.

4. **Explications**, six étapes :

   - « Écrire et voir » (3 écrans) : Emmet et le squelette (seulement l'obtenir) ; une extension s'installe depuis le panneau Extensions ; l'aperçu Live Preview.
   - « Le terminal intégré » (2 écrans) : il s'ouvre dans le dossier du projet ; son profil se choisit.
   - « Éditeur, IDE et extensions » (3 écrans) : éditeur contre IDE ; une extension de langage n'installe pas le langage (E2) ; la synchronisation des paramètres (E3).
   - « Choisir son outil » (4 écrans) : VS Code n'est pas Visual Studio (E1) ; quel IDE de JetBrains pour quel langage ; les licences (E4) ; choisir pour un besoin donné.

5. **Pratique** : douze items, chacun avec sa variante, dans cinq groupes qui vont de la ligne déjà classée à l'exercice seul (ouvrir : architecture, `code .`, le terminal ; écrire : Emmet ; extension et synchronisation : classements ; choisir : Visual Studio, IDE et langage, licence, besoin ; IA).
6. **Atelier** (règle F06) « Sur ta machine » : sept écrans, une consigne par écran (le dossier de travail et ton architecture ; installer VS Code ; ouvrir le projet ; le squelette ; l'aperçu ; le terminal intégré ; ton choix par écrit), commun aux deux systèmes sauf ce qui diffère (outil `systeme`) ; crans « Un indice », « Une piste détaillée », « Une partie de la solution » : une question, un indice, l'étape détaillée, jamais la réponse.
7. **Ensemble** « Reviens sur ton pari » : le pari repris et corrigé ; la chaîne construite pour Noah ; à retenir, la suite et ce qui reste à explorer plus tard.
8. **Restitution**, **rappel**, **différées**, **bilan** : voir le manifeste. La restitution reprend la relation centrale sur un cas nouveau, sans support.

## 8. Le tableau d'alignement et la liste

Une ligne par notion de la section 10, une ligne par relation centrale (`relations`), une ligne pour le tout (`ensemble`), avec `hors_objectif`. Chaque ligne : l'étape qui la montre, ce qui l'entraîne, les questions qui l'interrogent.

« La liste avant d'écrire un écran » d'AGENTS.md, recopiée mot pour mot (à avoir sous les yeux à chaque écran) :

Trois blocs ont fait la même dizaine de fautes, trouvées après coup par les épreuves ou par Amine. La machine en attrape une partie ; le reste se relit à l'écriture de chaque écran, cette liste sous les yeux, puis à la relecture de la fiche. Une faute de cette liste trouvée aux épreuves est une faute de méthode, pas de hasard.

1. **L'écran se résout avec ce qu'il montre.** La règle, la convention, la donnée qu'il faut sont écrites plus haut sur l'écran ou dans l'encadré « Pour lire » ; rien n'est expliqué trois écrans plus loin (B03 : le disque de 931 Go). Une règle montrée sur un seul exemple n'est pas enseignée.
2. **Une consigne, une question.** Le rappel va dans l'encadré ; la question tient en une phrase, un seul temps (« relève, puis juge » fait deux items), et ne souffle pas sa réponse.
3. **Le retour oriente, il ne répond pas.** Une question ou un indice sur la notion ; ni les mots de la bonne option, ni l'attendu, ni la solution. L'encadré « Pour lire » redit une convention, pas la règle que l'exercice vérifie (B03 : « Le vendeur »).
4. **Le mot est celui du modèle**, défini avant d'être employé (« architecture », pas « famille ») ; un mot du métier qui n'est pas défini (tableur, rendu, export, tour) se remplace ou se définit sur place.
5. **Rien de la conception.** Pas de temps ni d'étape numérotés, d'identifiant d'onglet, de nom de classe, d'étiquette de la méthode, de gabarit « [seulement si l'essai est faux] » dans le texte.
6. **La situation revient et l'écran se lit sur un téléphone.** Chaque écran repart de l'histoire du bloc, quatre écrans abstraits d'affilée au plus ; un calcul s'écrit en lignes, pas en ligne continue ; pas une douzaine de noms ou de codes d'un coup (B03, ET8).
7. **Peu de prénoms**, un par cas, le même d'un bout à l'autre du cas (B03 en avait 17).
8. **La charge se compte en écrivant.** Les saisies de l'écran s'ajoutent au total du bloc (B03 : environ 115) ; un exercice qui n'apporte ni notion ni erreur nouvelle se fond dans un autre.
9. **Ce qui se fait hors de la page a son constat** (règle F06), et le mot de l'outil est vérifié (« Enregistreur audio » sous Windows 11 ?).
10. **La grille se recompte avec la fiche** : chaque nombre, chaque citation, la version.

## 9. Contraintes de style et de fond

- Français, tutoiement, accents, aucun tiret cadratin (ni — ni –), phrases courtes, un mot du métier défini avant d'être employé. Un mot, un seul sens du début à la fin : « éditeur » (VS Code) et « IDE » (défini avant l'opposition) ; « projet » (un dossier ouvert dans l'éditeur, défini en ET4) ; « extension » (définie à son premier emploi, avec son panneau) ; « architecture » défini une fois (ce que ton processeur sait exécuter : x64 ou ARM64), avec comment lire la sienne ; « PATH » défini une fois (la liste des dossiers où la fenêtre cherche une commande) ; « palette de commandes » ; « profil » du terminal ; « licence » (le droit d'utiliser un logiciel, avec ses conditions) ; « usage commercial » (un travail payé) ; « synchronisation des paramètres » ; « Emmet » ; « squelette » (les lignes de base d'une page HTML) sans jamais expliquer le HTML.
- Le texte de l'apprenant ne dit rien de la conception : pas « étape N », pas « Avant de lire », pas de nom de classe, d'identifiant d'onglet, de temps numéroté.
- Chaque écran se résout avec ce qu'il montre : la donnée (la ligne lue, le message de la fenêtre) est imprimée sur l'écran ; ce que fait chaque raccourci, option ou commande citée est redonné dans un encadré « Pour lire » (une convention, jamais la conclusion de l'exercice).
- Un exercice du cours se pose AVANT le texte qui répond ; ce texte ne paraît qu'une fois l'exercice fini. Une consigne, une question ; le retour d'une option fausse et les coups de pouce sont des questions qui orientent.
- Un écran, une notion, au plus trois mots nouveaux ; quatre écrans abstraits d'affilée au plus ; le projet de Yasmine revient dans chaque étape.
- **Faits de licence, écrits prudemment** (ma connaissance la plus sûre, sans prix ni date qui change) : VS Code est gratuit, y compris pour un travail payé ; Visual Studio est un autre produit, dont l'édition Community est gratuite sous conditions (la fiche ne les détaille pas) ; les IDE de JetBrains sont des logiciels payants, avec deux voies gratuites (une licence étudiante, pour apprendre, sur preuve de statut ; un mode non commercial, qui exclut un travail payé) ; PhpStorm n'a pas d'édition Community, alors qu'IntelliJ IDEA et PyCharm en ont eu une, que JetBrains a fait évoluer depuis ; la page dit « à la date de cette fiche : lis la page de licence de l'IDE avant de décider » et ne cite aucune date ni aucun prix. **À confirmer par Amine** (liste « À toi de trancher ») : (a) PhpStorm gratuit en usage non commercial (annonce récente de JetBrains) ; (b) le sort des éditions Community d'IntelliJ IDEA et de PyCharm (fusion en une distribution unique, niveau gratuit) ; (c) le nom exact de l'offre étudiante ; (d) les conditions de Visual Studio Community.
- **Faits joués** sur Ubuntu : `command -v code` ne répond rien (VS Code n'est pas installé : cela illustre « la commande n'est pas dans le PATH ») ; `uname -m` répond `x86_64` ; `echo $PATH` donne une liste de dossiers séparés par deux-points. La fiche cite `uname -m`, `x86_64` et `aarch64` comme sorties de la fenêtre d'Ubuntu.

## 10. Les notions à couvrir

14 notions, chacune dans au moins une relation (section 4).

- N1 Ouvrir un dossier comme projet depuis la fenêtre : se placer dans le dossier (`cd`), `code .` ; `.` désigne le dossier courant ; la commande `code` doit être dans le PATH ; `code --version` le vérifie et écrit trois lignes. Installer VS Code est fourni (« Installer VS Code »).
- N2 Choisir l'installateur selon l'architecture : x64 ou ARM64, lire la sienne (`uname -m`, « Type du système », « À propos de ce Mac », la troisième ligne de `code --version`).
- N3 Emmet : l'abréviation `!` suivie de Tab développe le squelette HTML dans un fichier `.html` ; on obtient le squelette sans le lire.
- N4 Une extension s'installe depuis le panneau Extensions ; Live Preview affiche la page dans l'éditeur et se met à jour quand on modifie et enregistre le fichier.
- N5 Le terminal intégré s'ouvre dans le dossier du projet ; son profil (bash, Cmd, PowerShell) se choisit.
- N6 Éditeur contre IDE : un éditeur écrit du texte et s'étend par extensions ; un IDE réunit en plus débogage, analyse du code et outils du langage.
- N7 Une extension de langage n'installe pas le langage : coloration et aide, pas d'exécution ; le langage s'installe sur la machine.
- N8 La synchronisation des paramètres transporte réglages, raccourcis et extensions, pas les dossiers de projet.
- N9 VS Code n'est pas Visual Studio : deux produits de Microsoft, un éditeur gratuit et un IDE à part.
- N10 Quel IDE de JetBrains pour quel langage : PhpStorm pour PHP, WebStorm pour JavaScript, PyCharm pour Python, IntelliJ IDEA pour Java.
- N11 Les licences : VS Code gratuit ; IDE JetBrains payants avec licence étudiante et mode non commercial ; PhpStorm sans édition Community ; ne jamais décider sans lire la page de licence à jour.
- N12 Choisir entre VS Code et un IDE de JetBrains pour un besoin donné : langage, travail payé ou non, machine, architecture.
- N13 Pendant l'apprentissage, on tape le code soi-même ; le code généré par une IA n'est pas une preuve.
- N14 La palette de commandes lance une commande par son nom (dont celle qui met `code` dans le PATH sous macOS).
